## 账号与权限

| 账号角色 | 可以操作的内容 |
| --- | --- |
| 员工 | 登录查询、分类筛选、图片检索、收藏产品、保存及查看自己的选型方案、查看实物样品资料与流转记录 |
| 管理员 | 员工功能，以及进入后台维护产品资料、图片、分类、网站内容、样品、方案和账号，查看修改记录与导出资料 |

原有员工账号保持员工角色，不会因为升级自动变成管理员。普通员工不能修改产品、报价、实物样品档案或网站设置，也不能调用后台接口写入这些资料。

在“员工与权限”创建独立账号，填写登录账号、员工姓名、角色和初始密码。登录账号创建后保持不变；管理员可以修改姓名、调整角色、停用账号，或填写新密码重置密码。重置密码栏留空表示保持原密码。

新密码需为 12–300 个字符，首尾不能有空格。密码修改、角色修改和停用账号会使该账号已有登录状态失效，需要重新登录。系统拒绝停用或降级最后一个启用的管理员。不要将管理员账号交给普通员工共用。

## 维护产品资料

在“产品资料”中搜索编号、名称、材质或供应商，点击“编辑”；新产品使用“新增产品”。后台分为四组：

1. **基础资料**：名称、资料类型、包材分类、瓶型、标准材质、容量、规格说明、系列、款式型号、用途和产品说明。
2. **供应商与报价**：供应商、联系人、采购报价原文、报价口径、MOQ、货期，以及可选的确认单价、币种、有效期、样品费用和历史定制信息。
3. **产品图片**：上传、说明、用途、排序和移除图片关联。
4. **其他与来源**：备注、来源补充、待确认事项及只读的原始单元格与出处。

名称为必填项，其他资料尚未确认时可留空。一个系列的不同规格分别建记录，并使用相同系列名称关联。容量字段单位是 mL；重量、尺寸、片数、套数等写入规格说明，不能直接当作容量。

“标准材质”和“用途标签”可填写多个值，以顿号或逗号分隔。原始描述保存在“材质说明”“规格说明”等原文字段中。材料、适配料体、MOQ、报价、币种、货期或有效期没有依据时，不根据图片、名称或其他供应商资料推断补齐。

采购报价支持“1 万个以上 1.2 元”等文字，不要求每条报价拆成数字。确认单价、币种和报价有效期是可选字段；有效期格式为 `YYYY-MM-DD`。

印刷工艺不要求逐款录入工艺价格。已有历史工艺原文可以维护；后续在“网站内容”录入统一参考标准。系统不据此自动计算工艺费用、MOQ、货期或最终报价，由业务员结合实际要求判断。

原始文件名、图册页码、工作表、行号、原始单元格、原始映射信息保留为只读证据。修订当前字段不会覆盖原始资料；新资料出处、图册页码及更正依据写入“来源补充说明”。OCR 提取内容在核对前保留待确认标记，不用其他款式的参数或报价填补空缺。

### 产品图片与搜图索引

上传支持 JPEG、PNG、WebP，单张原文件不超过 10 MB。页面会检查图片尺寸并缩放后上传，服务器重新编码保存；每条产品最多保存 30 张图片。上传成功后还需要点击“保存产品”，图片才会与该产品建立正式关联。

图片可前移、后移、设为首图或移除。员工页面优先展示排序靠前且符合展示条件的产品、供应商或询价图片；只有共用参考图时会明确标注为整页／参考图。图片角色为“参考图片”及其他参考类时，不进入相似图片检索；原始资料中存在的对应关系待确认标记保留为只读提示。

`source_page` 使用明确关联的原资料图片建立整页索引，检索结果标注原页／图片线索。它与产品详情中的共用参考图用途不同：整页相似只提供查找线索，需要继续打开原图、型号和关联产品核对，不能据此声称完成单品识别。独立 `process_rule` 资料不作为产品搜图候选。

图片排序、角色及关联变更在保存后生效。产品、图片更新后会自动更新搜图索引，产品列表底部显示索引状态；如更新失败可点击“更新搜图索引”重试。上传成功与索引完成是两步，不能将尚在更新的图片当作已经可搜到。

从当前产品移除图片只移除关联，保留历史版本使用的图片。不要手动清理服务器上传目录中的“看似没使用”文件，否则旧版本或历史方案可能无法显示原图。

### 归档、恢复与版本冲突

不再展示的资料使用“归档”。归档后产品从员工当前产品库隐藏，后台勾选“包含已归档”后仍可查看和编辑，点击“恢复”重新展示。编辑已归档记录不会自动恢复展示；历史选型方案保留当时快照，不因产品归档或修改而改写。

点击产品“历史”可查看历次保存内容，选择“恢复此版本”将当时的完整产品内容保存为一个新版本。恢复操作本身也会留下记录，不删除中间版本；恢复历史内容不自动改变当前归档状态。首轮管理修改会保留原始版本，方便回到初始资料。

所有保存都核对版本号。如果同一资料在打开后被另一人或导入操作修改，系统拒绝覆盖并提示版本冲突。先保留需要的输入，再关闭、重新打开最新资料，合并后保存。不要反复提交旧页面尝试强行覆盖。

## 分类词表与网站内容

“分类与检索标签”分别维护包材分类、材质、瓶型与结构、用途／料体类型，每行一个标签。它们是相互独立的维度：例如“玻璃”是材质，“圆瓶”是瓶型，“50 mL”是容量，不能全部混在一个类别里。

修改词表后员工页面重新读取可用分类和筛选标签。词表的增删改不会批量重写既有产品字段；更改标签名称后，如需统一旧数据，仍需编辑对应产品或使用导入更新。分类或用途标签仅用于检索，不代表已经完成料体兼容性验证。

员工左侧按资料类型、包材类别、材质、容量区间和来源图册／表格浏览，顶部可继续筛选精确容量、瓶型、用途与报价资料。条件可以组合，也可在已选标签上逐项清除或使用“清除筛选”重置。容量区间按下限包含、上限不包含区分；侧栏数量注明为全部产品的分类数量，不是当前组合筛选的结果数量。

图册与图片线索、工艺与价格参考分别展示。切换资料类型会清掉不适用的产品条件；来源筛选按当前资料类型提供文件列表。`50毫升`、`50ml` 和全角输入统一单位，PET 与 PETG 保持不同材质。

“网站内容”可维护品牌中文名、英文名、公司名称、浏览器页面标题、展厅标题与说明、页脚、站内公告、印刷工艺参考标准，以及业务演示入口的显示状态。保存后员工刷新页面查看最新内容。

## 实物样品与选型方案

“实物样品”只登记实际收到的样品。新增时填写独立样品编号、关联产品编号、存放位置和状况。管理员可以修正位置、状况、状态、借用人及预计归还日期；已有样品编号保持不变。

状态为“已借出”时必须填写借用人和有效的预计归还日期。改为在库、耗用或寄出时，应清空借用人和归还日期，并填写对应位置与状况。更正、归档、恢复均保留管理审计和样品流转历史，不覆盖旧事件。

“选型方案”可查看员工保存的方案，修改名称、备注或归档／恢复。方案中的产品快照保持创建时的内容，不能用后台改成当前价格或新产品参数；需要新的选型依据时，在员工页面另存新方案。

## 批量导入与导出

建议先从“批量导入与导出”下载 CSV 模板。模板仅含表头，没有示例产品，避免误导入演示数据。

1. 按模板整理 `.csv` 或 `.xlsx`。XLSX 必须只有一个工作表；每次不超过 10 MB、2,000 条数据行，正文数据也有总量限制。大型原始报价工作簿应先整理为精简导入表。
2. 产品名称必填。新增产品可留空记录编号，由系统生成；更新产品必须同时填写现有编号和该记录的当前“版本”号。更新行缺少版本号时预览直接报错，不会用数据库当前版本代替，因此旧表不会覆盖预览前发生的编辑。版本号只在新增行可以留空；填写的版本与当前版本不一致时，整批导入被拒绝。新写的未知编号会建立新记录，因此要核对拼写，避免误建重复产品。
3. 点击选择文件，检查预览中的新增、更新内容和错误。所有错误修正后重新选择文件，才可确认导入。页面最多展示前 50 条预览，确认时处理整个已校验文件。
4. 点击“确认导入”。预览有效期为 30 分钟，每次确认使用一次预览。预览之后任何相关记录发生修改，会使整批导入回滚，不会留下部分成功的数据；重新预览、核对后再确认。

导入表中**存在的列**会更新对应字段，空单元格可以清空旧值；**不存在的列**保持旧记录原值。只更新少量字段时，使用模板支持的列并保留“名称”、记录编号和“版本”，去掉不准备修改的列，避免完整空白模板覆盖现有信息。版本号取自产品 CSV 导出或上一次导入文件；不要手工填写比当前更大的数字。

CSV 建议保存为 UTF-8。XLSX 公式需先复制并粘贴为值；含宏、外部工作簿链接、多工作表或不支持表头的文件会被拒绝。导入不会执行公式，不会直接解析 PDF，也不会根据照片补齐缺失参数。

Excel 内嵌图片不随表格导入；在对应产品编辑页单独上传。表格中的出处说明写入“来源说明”，不会覆盖原始来源证据。缺失信息保持空白，不能把其他款式、规格、数量条件的报价直接套用。

页面提供产品 CSV 和完整产品 JSON 导出，包含已归档产品。CSV 适合人工核对常用字段；JSON 保留产品完整字段、图片关联及来源。当前产品 CSV 使用导入支持的字段，可在保留编号及版本号后编辑并重新上传预览。归档状态、图片和完整来源等不通过 CSV 批量覆盖；需要完整记录时使用 JSON。回导仍核对版本，不能跳过预览直接覆盖。

管理员还可访问 `/api/admin/export` 下载业务管理 JSON，包含产品、原始记录、账号公开资料、网站设置、分类、样品、方案、全部审计和流转事件，不包含密码散列。这是业务资料导出，**不是可直接恢复整个系统的服务器备份**；图片文件、账号认证数据库及其他状态仍需按下述方式备份。

## 服务端状态、备份与升级

服务器运行状态目录由 `YZ_STATE` 指定；现有部署使用 `/var/lib/yuanze-reference`。后台修改保存在此目录，不能随代码升级清空或替换。

主要持久化内容：

| 位置 | 内容 |
| --- | --- |
| `catalog.sqlite` | 产品当前内容与原始证据、账号密码散列、分类与网站设置、审计、实物样品、方案、收藏及图片关联登记 |
| `admin_uploads.sqlite` | 上传图片登记、内容校验摘要 |
| `uploads/` | 管理员上传的图片文件 |
| `image-search/` | 动态搜图索引及相关缓存 |
| `auth.json`、初始化账号文件（如仍保留） | 认证初始化与迁移资料，属于敏感服务器配置 |

备份需要让两个 SQLite 数据库和上传文件处于同一业务时间点。最直接可靠的做法是安排短暂停机：停止 `yuanze-reference` 应用服务，确认进程退出，使用 Python `sqlite3.Connection.backup()` 分别备份 `catalog.sqlite` 与 `admin_uploads.sqlite`，同时复制 `uploads/`、`image-search/` 和必要的状态配置，再启动应用。备份文件仅由运维人员读取，并保存到状态目录之外的受保护位置。

如果必须不停机，单独对两个数据库调用 backup API 只能保证每个数据库自身一致，不能保证跨库与图片文件是同一时间点；需另有统一暂停写入及文件快照方案。不要运行中只复制 `.sqlite` 主文件而遗漏 WAL。恢复备份也需停服务，在受控目录先验证数据库可打开、上传登记与文件对应，再恢复服务用户的文件权限并启动验证。

同时保留对应代码发布版本、原始 `private/catalog.json`、原始 `private/media/`、图片模型与依赖版本。新代码放入独立 release 目录，验证后切换当前版本；不要用 release 内容覆盖 `YZ_STATE`，也不要重新执行首次安装脚本来升级已有实例。代码回退与业务数据回退是不同操作，回退前先备份当前状态，避免丢失升级后的录入。

当前 release 为 `/opt/yuanze-reference/releases/20260927-materials-v1`，运行环境沿用 `/opt/yuanze-reference/venvs/admin-20260924`。本次升级前备份已保存至 `/opt/yuanze-reference/backups/20260927-before-materials`；此前的 `20260924-before-admin` 仅是较早历史备份。上一代码版本为 `/opt/yuanze-reference/releases/20260924-admin-v1`。

回退至上一版本后，旧界面或检索逻辑可能不能完整显示 `source_page`、`process_rule`，旧 release 也可能缺少新增原页媒体。需核对新记录、原始媒体路径、权限和索引兼容性，再恢复员工访问。代码回退不自动恢复旧数据库；当前数据和新增修改应保留，只有另行确认需要恢复数据、已备份当前状态并核实影响后，才恢复指定一致性备份。详见 `deploy/DEPLOYED.md`。

正常更新上线后检查：员工仍可查询和选型、后台权限隔离有效、管理员修改能持久保存、上传图片可显示、图片索引可完成更新，以及重启后设置和账号仍保留。备份是否有效应通过独立临时环境恢复核验，不能仅依据备份文件存在来判断。

## 范围说明

本后台接管的是自建包材库，不是原外部 ERP 系统。网站保留的 `/business/index.html`“业务系统演示”仍使用演示数据，未接入正式样品配方、采购、生产、仓库、财务或旧系统账号；后台仅控制演示入口是否显示，不提供对演示页全部业务数据的正式管理。

本次已把文字条目、原页线索与独立参考规则分开入库，不表示 PDF 中每个单品都已分割、去重、核实参数并建立独立图片索引。后续新素材仍需整理出处、关联图片并检查索引进度；价格、MOQ、货期和适配信息有明确依据后再填写。
