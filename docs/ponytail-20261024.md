# Ponytail 第一轮：资源清单读取优化

日期：2026-10-24。状态：隔离分支的本地候选，未部署；不分配新的客户端界面版本。

原版恢复点：`rollback/ponytail-20261024-before`，提交 `a254d2c05e7f8da61d21d5c862988bca046faa81`。
该恢复点包含已有的 client1.7 图片加载和触控板防误返回本地修复，不等于线上版本。

## 改动

- 登录与展厅资源共用清单读取校验，通过标准库 `lru_cache(maxsize=4)` 保存最多四份文件名集合。没有新增依赖。
- 每次请求重新读取清单的设备、inode、大小、纳秒修改时间和状态变更时间；原子替换、原位修改、删除或损坏时不复用旧批准结果。
- 两个入口都要求 `schema=1` 且 `files` 为对象，修复登录入口曾接受列表或字符串的不一致。
- 路径白名单、文件存在/符号链接检查以及 HTTP 登录和角色检查继续每次执行。图片、界面、账号、数据库与生产服务未修改。

选择按文件状态失效的有界缓存，避免每个资源请求重复解析；不采用永久缓存或定时失效，以免清单撤销后仍放行旧条目。并发首次请求可能各自解析一次，后续复用；无需新增互斥队列。

## 验证与恢复

新增 `test_bundle_manifest_cache.py` 覆盖重复读取、相同大小/mtime 的替换与原位修改、删除/损坏/恢复、文件删除及符号链接逃逸、读取失败重试。沿用登录、展厅、三角色权限、ETag 和 Range 的 HTTP 回归，并执行 `scripts/verify.py`。

本机 384 项展厅清单、每轮 460 次查找、7 轮中位数：原版 63.53 ms，候选 24.47 ms，清单检查耗时减少约 61%。这不是页面、网络或生产响应的测速。

部署前应合并实时服务器差异并执行现有发布门禁；不能将本地未发布的其他修复一并覆盖上线。未来撤销本次优化应优先反向提交本次改动，保留后续工作；恢复整个基线只应在明确选择的隔离副本中进行。Git 不包含生产数据库、私有素材或密钥备份。
