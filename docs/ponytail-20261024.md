# Ponytail 第一轮：资源清单读取优化

日期：2026-10-24。状态：12:47:35 已上线并通过公网验收；不分配新的客户端界面版本。

原版恢复点：`rollback/ponytail-20261024-before`，提交 `a254d2c05e7f8da61d21d5c862988bca046faa81`。
该恢复点包含已有的 client1.7 图片加载和触控板防误返回本地修复，不等于线上版本。

## 改动

- 登录与展厅资源共用清单读取校验，通过标准库 `lru_cache(maxsize=4)` 保存最多四份文件名集合。没有新增依赖。
- 每次请求读取清单字节内容作为缓存键；原子替换、原位修改、删除或损坏时不复用旧批准结果。
- 两个入口都要求 `schema=1` 且 `files` 为对象，修复登录入口曾接受列表或字符串的不一致。
- 路径白名单、文件存在/符号链接检查以及 HTTP 登录和角色检查继续每次执行。图片、界面、账号和业务数据保持；上线只替换 server.py 并重启应用一次。

选择按文件内容失效的有界缓存，避免每个资源请求重复解析；不采用永久缓存或定时失效，以免清单撤销后仍放行旧条目。并发首次请求可能各自解析一次，后续复用；无需新增互斥队列。

## 验证与恢复

新增 `test_bundle_manifest_cache.py` 覆盖重复解析复用、相同大小/mtime 的替换与原位修改、删除/损坏/恢复、文件删除及符号链接逃逸、读取失败重试。沿用登录、展厅、三角色权限、ETag 和 Range 的 HTTP 回归，并执行 `scripts/verify.py`。

原时间戳候选在服务器上暴露同一时间戳内改写的问题，已改为内容键并新增确定性回归覆盖；旧候选 61% 的函数基准不适用于最终实现。最终内容键版本同机 384 项清单、460 次查找、7 轮中位数为 68.03→32.21 ms，约减少 52.65%，仅代表本地函数检查，不是页面或生产测速。
