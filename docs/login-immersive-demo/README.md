## 启动

本目录使用 Node.js 22+、pnpm：

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm build
pnpm preview
```

打开 `http://127.0.0.1:8772/login`。`pnpm dev` 也会先构建后启动同一安全预览服务，不提供热更新；修改后重新 build 即可刷新。不要用纯静态服务器或 `vite preview` 代替 `preview-server.js`，它们没有真实认证转发功能。

## 真实登录与隔离范围

- 原版 demo 的内存模拟拒绝正式账号，是此次登录故障的原因。已删除模拟账号、模拟 transport、演示成功页和演示工具栏。
- 默认复用正式工程 `server-reference/public/api-client.js`：POST `/api/login` 仅提交 username/password，随后 GET `/api/session` 验证会话和角色，再实际跳转客户 `/client`、业务 `/`、管理 `/admin`。合法产品 code 按原规则保留。
- `preview-server.js` 只监听 **127.0.0.1:8772**。本地提供新登录页及 `/_login/` 资源；其他路由转发到固定的 `https://bmt.yuanzebeauty.com`，保持生产页面和权限检查。
- 固定 Host / Origin 检查阻止其他网站或域名利用代理；上游 HTTPS 保留证书验证。Cookie 的 Secure / HttpOnly / SameSite 保持原样，不降级、不在脚本中保存会话。登录请求不会自动重试，不记录账号、密码、Cookie 或请求正文。
- 此预览使用真实账号，会进入真实工作区；工作区中的操作作用于真实数据。新登录界面尚未部署线上，另一台电脑的代码、页面和服务均未覆盖或重启。
- 错误区分凭证不正确、网络/服务异常、超时、限流和会话异常，不再误导用户使用演示账号。

## 当前双视频布局

当前使用 `scripts/build-glow.py` 生成的原创橙粉双光团循环视频：暖橙底、奶油色柔光边缘、粉色光团沿错开的路径漂浮、呼吸伸缩并轻微变形，10 秒平滑循环。使用仓库 `.venv` 中的 NumPy / Pillow / imageio-ffmpeg 可复现生成；动画在离线阶段编码，不在浏览器中逐帧绘制。原用户视频 `包材库素材/0.mp4` 及上一版网页副本保留。

- 同一个 MP4 放置两次：全屏固定视频 `object-cover` / 105% 缩放，叠加 10% 黑色遮罩和 `backdrop-blur-sm`；左侧视频清晰显示，没有覆盖全幅的遮罩。
- 白色卡片最大宽 1040px，桌面最小高 650px，内侧左 45% / 右 55%；390px 手机视频高度 225px，320px 窄屏为 200px，下方排列账号密码表单。
- 右侧为左上淡橙、右下淡粉的渐隐光晕，以 10 秒周期缓慢呼吸，融入白底；装饰层不接收鼠标事件或键盘焦点。标题、输入框、原 LOGO 保持清晰。
- 保留原源泽标志、账号密码、语言切换、密码显隐和原真实认证流程；未增加社交、邮箱登录或注册入口。
- 左侧视频右下角控件统一暂停/恢复两层视频与表单光晕，恢复时对齐视频播放位置，不进行逐帧寻址。隐藏标签页或视频滚出视口只临时暂停，回到可见状态自动继续；手动暂停、减少动态效果、省流模式和自动播放受限不会被可见性变化覆盖，须主动点击播放。初始在后台加载时也会等待可见再播放。表单重渲染不重新挂载或启动视频。
