# 源泽包材库：后端与数据库说明

核对日期：2026-09-29。结构以当前代码为准；下面明确标注的线上统计来自对阿里云服务器的只读查询。本轮整理结构、数据职责、检查入口和维护规则，不删除记录、不改密码、不执行数据库迁移。

## 数据在哪里

```text
员工 / 管理员 / 客户浏览器
              ↓ HTTPS
       Caddy 网关与登录门禁
              ↓ 127.0.0.1:4180
       server.py：路由、认证、权限
              ├─ AdminStore → catalog.sqlite
              ├─ SessionStore → auth-sessions/sessions.sqlite
              ├─ UploadManager → admin_uploads.sqlite + uploads/
              ├─ ClientCatalog → 批准图片、容量、不透明链接
              └─ ImageSearch → 原图、模型、可重建索引
```

线上代码：`/opt/yuanze-reference/current` 指向当前 release。线上可变数据：`/var/lib/yuanze-reference`。发布代码不能覆盖可变数据目录。

**桌面工程的 `server-reference/state/` 不是生产数据库备份。** 本次只读检查显示，它只有四张空的早期业务表。不要用它覆盖服务器，也不要为了检查数据库而启动应用——应用启动会执行初始化和种子导入。

## 后端职责

| 模块 | 负责内容 | 维护边界 |
| --- | --- | --- |
| `server.py` | HTTP 路由、登录、同源/CSRF 检查、角色隔离、员工业务接口 | 每个接口独立检查权限；前端隐藏按钮不等于授权 |
| `admin_store.py` | 产品、账号、配置、导入保存、版本冲突、审计 | 修改当前数据，保留原始资料与历史 |
| `auth_sessions.py` | 持久会话、过期、撤销、并发数量 | 改密码/停用后旧会话失效，常规重启保留有效会话 |
| `admin_imports.py` | CSV/XLSX 的有界解析和校验 | 预览不写业务数据；提交检查记录版本 |
| `admin_images.py` | 上传、文件登记、动态索引协调 | 上传完成、关联产品、索引完成是不同阶段 |
| `image_search.py` | 图片校验、向量索引、相似排序 | NumPy/Pillow/ONNX 和后台计算，不是普通静态页面功能 |
| `client_catalog.py` | 客户专用数据和图片出口 | 只允许批准图片、系统编号、标准分类与数值规格；每次取图重查批准/归档状态。供应商、报价、自由文本与来源不进入客户接口 |

## 三个数据库、十六张业务表

`catalog.sqlite` 保存 14 张业务表，SQLite 自己的内部表不计入。

| 表 | 数据用途 | 必须保留的规则 |
| --- | --- | --- |
| `admin_records` | 当前产品/资料 JSON、原始证据 JSON、版本、归档状态 | 当前字段与原始证据分开；未知参数留空 |
| `admin_product_codes` | 产品内部 ID 与 `YZ-BC-` 编号映射 | 编号唯一、不可修改、不可删除回收 |
| `admin_product_code_sequence` | 下一个编号 | 不重新从 1 分配，不因归档重用编号 |
| `admin_users` | 角色、启停、密码散列、账号与认证版本 | 三种角色明确隔离，不输出认证材料 |
| `admin_config` | 网站设置和分类词表 | 配置变化不自动重写全部产品 |
| `admin_audit` | 修改前后内容、操作者、时间 | 历史不是重复产品，不能当冗余行删除 |
| `admin_entity_meta` | 方案、样品等业务实体版本与归档 | 保留乐观锁语义 |
| `admin_uploads` | 上传路径、上传人和时间 | 业务审计用途，不等同文件校验登记 |
| `admin_migrations` | 已完成的初始化/导入标记 | 不能通过清空标记重复执行导入 |
| `preferences` | 员工收藏 | 按登录账号隔离 |
| `plans` | 选型方案和当时产品快照 | 历史快照不能被当前报价覆盖 |
| `samples` | 实物样品、位置、状态、借用人 | 是实物记录，不代表全部图册有库存 |
| `movements` | 样品流转历史 | 与样品关联，保留时间顺序 |
| `client_media_map` | 客户图片代号与内部记录/路径对应 | 不向客户返回内部路径、供应商或价格 |

另外两库各有一张表：

| 数据库 / 表 | 用途 |
| --- | --- |
| `admin_uploads.sqlite` / `uploads` | 上传文件路径、SHA256、时间，用于登记与校验 |
| `auth-sessions/sessions.sqlite` / `sessions` | 会话 token 的哈希、账号、CSRF、过期时间、认证版本与角色 |

当前没有独立的“供应商表、报价表、产品图片表”：相应字段在产品的 `content` JSON 中。不能将建议的新结构误写为现有实现。未来拆表须保持记录 ID、版本和原始证据的对应关系。

## 原文件、当前数据、缓存的区别

| 位置 | 性质 | 处理方式 |
| --- | --- | --- |
| release 的 `private/` | 原始图册/询价底稿、原图、可信图片对应关系 | 作为来源证据保存，不覆盖当前数据库修改 |
| state 的三个 SQLite 文件 | 当前数据、账号、操作历史与会话 | 一致性备份，不能仅复制正在写入的主文件 |
| state 的 `uploads/` | 管理员上传图片 | 和文件登记及产品关联共同备份 |
| state 的 `client-media/key` | 客户图片代号所用密钥 | 保密保存；恢复时与映射对应 |
| state 的 `client-media/` 图片 | 受控输出图片的派生缓存 | 可重建，但不能删掉目录里的密钥 |
| state 的 `image-search/` | 动态索引/向量缓存 | 可重建；原图及模型配置仍须保留 |

## 只读检查命令

在有权限读取状态目录的机器运行：

```sh
python3 scripts/database_inventory.py --state /var/lib/yuanze-reference
```

工具使用 SQLite 只读连接及 `query_only`；仅返回表/字段、行数、索引和聚合检查结果，不输出产品原文、密码散列或会话值。不存在的文件不会被创建。退出码 0 表示本次检查通过；缺库、不可读、损坏、外键异常或包材缺编号均返回 1。不同数据库分别读取快照，不宣称是跨库同一时间点。

桌面本地执行时将 `--state` 改为 `server-reference/state`；由于本地不是完整线上副本，缺失数据库会被明确报告。完整代码验证：`python3 scripts/verify.py`。

## 备份、恢复与后续整理顺序

1. 备份同时覆盖当前 release、三个数据库、上传文件、私有来源文件、客户图片密钥及必要部署配置。凭据独立保管，不进入 Git。
2. 涉及一致性恢复点时暂停业务写入，通过 SQLite backup API 备份数据库，再复制对应文件；普通文件复制不能代替数据库备份。
3. 在隔离环境恢复，核对编号、数据版本、图片关联和三种角色。若带回会话，还须保留对应账号认证版本，并验证撤销规则。
4. 先统一重复的建表与迁移责任，再逐步拆分 HTTP 层与业务 SQL；每一步有独立测试和 commit。此项是后续代码重构任务，本轮未改运行时建表逻辑。
5. 当前员工目录由前端执行大量筛选。若数据继续增加，单独实施服务端分页和组合检索；不要在数据库梳理时同时改变查询语义。
6. 去重、拆报价表或清除图片要先产生可审核的差异清单。单凭同图、空字段、历史价格或表名相似不能删除记录。

本轮未新增线上表、删除数据、迁移账号或切换托管服务。Git 提交覆盖说明、检查工具与相应测试。
