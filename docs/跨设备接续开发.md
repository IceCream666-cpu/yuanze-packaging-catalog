## 新电脑首次接续

使用获准访问该私有仓库的 GitHub 账号。在已安装 Git 和 GitHub CLI 的电脑上执行：

```sh
gh auth login
gh repo clone IceCream666-cpu/yuanze-packaging-catalog
cd yuanze-packaging-catalog
git status
```

在 Codex 中打开克隆得到的目录。无需沿用原电脑的绝对路径，也不要将旧电脑的 Python 虚拟环境或 `node_modules` 直接复制过去。

按根目录 [README](../README.md) 安装 Python、Node 和依赖，运行：

```sh
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements-test.txt
npm ci
python3 scripts/verify.py
```

上面使用 macOS/Linux shell。Windows PowerShell 中可使用 `py -3 -m venv .venv`，随后直接运行 `.venv\Scripts\python.exe -m pip install -r requirements-test.txt` 和 `.venv\Scripts\python.exe scripts/verify.py`；Node/npm 仍需可用。正式运行搜图服务还需依据 `server-reference/IMAGE_SEARCH.md` 安装运行依赖与模型，合成回归测试不会下载模型。

## 多设备修改顺序

1. 开始前执行 `git status`；工作区干净时执行 `git pull --ff-only`。
2. 修改、补充测试，运行 `python3 scripts/verify.py`，检查差异后提交并 `git push`。
3. 切换电脑前确认提交已经推送；另一台电脑先拉取再修改。
4. 有未提交修改或分支分歧时先整理差异，不使用强制推送、硬重置或覆盖文件来跳过冲突。两台电脑并行开发不同任务时使用独立分支。

## 2026-10-07：自动上传 GitHub

正式工程已增加 `scripts/github_sync.py`。本机安装仓库专属的 `post-commit` 钩子后，每次完成修改、验证并创建提交，自动上传当前分支到上述私有仓库。其他 Codex 聊天只要操作同一个正式工程，也使用此钩子。独立克隆、旧工程副本不自动合并，以免覆盖正式代码。

新电脑完成 GitHub 登录后，在项目中安装：

```sh
python3 scripts/github_sync.py --install
```

上传失败不会丢失本地提交，下一次提交会再次上传全部待同步历史；也可以手动执行 `python3 scripts/github_sync.py` 重试。网络断开、GitHub 登录过期或远端分支分歧时，需恢复连接或整理冲突，不会强制覆盖远端。最近结果记录于本仓库 `.git/github-sync-status.json`，不上传该日志。上传需要电脑联网，不依赖 Codex 模型调用。

仅同步已经提交的代码、测试、文档和 Git 中的展示素材。不自动提交未完成编辑；密钥、密码、真实产品底库、运行数据库、图片处理工作目录继续排除。线上数据及全库图片应通过独立受控备份保存；GitHub 上传不等于网站重新部署。
