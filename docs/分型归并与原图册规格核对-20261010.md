## 本轮规则

展示按“原始来源、精确型号、实际包材类型”组织。同型号中的精华水／水乳瓶和膏霜罐分别显示；同一类型的不同容量归为一张系列卡片。每个容量继续使用原始产品编号、内部 ID、独立报价、收藏与管理员版本。不同型号、不同供应商、不同款式不能仅因共用照片就合并。

用户补充“图片没有具体参数时，原始产品图册有标注”。本轮以原始 PDF 的照片和对应容量表为依据，原始资料和价格条件保留。规格中的 g 与 mL 不换算；`50-20g` 等原图册复合标注保留原义，不擅自解释为直径或另造容量。存在表格参数而当前图片没有对应罐体时，问题属于图片对应待核对，不是缺少规格。

## 实现与验证

- `product-type-group-data.js` 保存逐页审核、规格与原始图片摘要；`product-single-group-data.js` 保存单一包材类型的归并定义。均不改写运行数据库。
- 原 PDF 内嵌照片原样提取；浏览器不支持的 JPEG2000 仅转换为无损 WebP。小图提供比例一致的轻量预览，主图区域由 CSS 裁切显示；未使用 AI 重绘或改变瓶型、材质与颜色。
- 原图与区域展示使用不同图片标识，避免图库去重将单品视图吞掉。图片失效时撤销旧裁切，换到备用原图，不套用旧区域或改变所选报价。
- 搜索、包材类型和瓶型筛选使用审核类型填补缺项；管理员明确维护的字段优先。每个规格只匹配其自身标签，避免整页 OCR 中其他容量引起误命中。
- 本地完整验证通过：102 项根测试、174 项后端测试、32 项部署测试及全部前端套件。新增 4 项图片交付测试与分型展示、原图保留、编号／规格定位、失败备用、来源关联的回归。
- 真实目录回放验证本轮 3,008 条规格均能按自身标签召回，原始目录未改写。390px 与宽屏布局验证主图完整显示；手机细节视图的尺寸比例问题已修复。
- 发布仅覆盖指定员工目录文件与新图片，不覆盖数据库、上传记录、账号、客户展厅或 Nginx 配置。发布完成后刷新目录查询子进程，使服务端分页和界面使用同一分型定义；登录服务不重启。
- 客户仍只能使用获批图片和安全字段。本次含供应商信息的原图及内部来源清单不会自动开放给客户；本轮不扩大图片批准范围。

私有证据为 `work/type-family-audit-20261009/`，包括候选清单、人工区域核对、原图 SHA、交付预检、完整测试、查询回放及部署材料。Git 不保存这些私有底稿或生产数据库。可用 `scripts/build_product_type_views.py --pdf-root <原图册目录>` 按审核摘要重新提取交付图片；源图摘要变化时会拒绝重建，要求重新核对。
